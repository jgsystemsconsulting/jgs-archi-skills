- name: archi-orchestrator
- description: Elicit architectural intent and produce a plain-language ArchiMate view plan via JGS Archi Bridge MCP (user-governed).
- argument-hint: optional free text intent

Skill body MUST:
1. **Elicit** (if missing) these fields in plain language: problem, stakeholders, concerns, scope, current state, target state, expected outcome (ORCH-01).
2. Optionally **read** MCP resources (cite only inventory URIs): `archimate://recipes/index`, `archimate://reference/archimate-view-patterns`, `archimate://reference/archimate-layers` — never paste full metamodel tables into the skill text.
3. **Produce a View Plan** markdown document with required sections exactly titled:
   - `## Intent Summary`
   - `## Stakeholders and Concerns`
   - `## Proposed Viewpoints` (each bullet: viewpoint name, purpose in plain language, stakeholders served, abstraction level in plain words e.g. overview/detail)
   - `## Layers Involved` (plain language + optional ArchiMate layer name in parentheses)
   - `## Modelling Sequence` (ordered steps)
   - `## Dependencies`
   - `## Validation Points`
   - `## Open Questions for User`
   - `## Confirmation Gate` stating user must approve scope before any create/mutate MCP tools run (ORCH-04)
4. Keep the main plan free of element-type catalogs; if types are needed, put under optional `## Appendix: Technical Hints` (ORCH-03).
5. **Do not** call create-element, create-relationship, create-view, bulk-mutate, or other mutating tools in this skill's happy path. Orchestrator stops at the confirmation gate. Specialists (later phases) perform creates.
6. After drafting the plan, run `python helpers/view_plan_schema.py <path-or-stdin>` when a file was written; fix sections until exit 0.
7. End by presenting the plan and asking the user to confirm, revise, or abort.
