# Roadmap: jgs-archi-skills

## Overview

Build a ZCode skill suite on the existing JGS Archi Bridge MCP: first stand up installable foundations and structural validation, then ship the user-facing orchestrator (OBJ-1 / SEED-001), ground viewpoint selection and specialist dispatch contracts, add inspect-before-create plus compliance, and close with rationale, completion summary, and live evidence. Later seeds deepen the full specialist set.

## Phase Details

### Phase 1: Foundations and MCP contract

**Goal:** Repo is an installable skill suite with a structural gate that skills only reference real Archi Bridge MCP tools/resources.
**Mode:** mvp
**Depends on:** Nothing (first phase)
**Requirements:** FOUND-01, FOUND-02, FOUND-03
**Success Criteria** (what must be TRUE):

  1. Install script places suite skills under `~/.zcode/skills/` from this repo
  2. Structural validation helper reports a clear failure when a skill cites an unknown MCP tool or resource name
  3. Docs state MCP default endpoint and the consume-only (no plugin fork) rule

**Plans:** 1/1 plans complete

Plans:

- [x] 01-01: MCP inventory, validator, install script, docs

### Phase 2: Orchestrator intent and view plan

**Goal:** A non-expert can run one orchestrator skill, provide intent, and receive a governed plain-language view plan (OBJ-1 / SEED-001).
**Mode:** mvp
**Depends on:** Phase 1
**Requirements:** ORCH-01, ORCH-02, ORCH-03, ORCH-04
**Success Criteria** (what must be TRUE):

  1. User invokes a single orchestrator entrypoint and supplies problem, stakeholders, concerns, scope, current/target state, and expected outcome
  2. Orchestrator returns a view plan naming viewpoints, layers, modelling sequence, dependencies, and validation points
  3. Plan is readable without ArchiMate expertise; user remains the decision authority on scope

**Plans:** 1/1 plans complete
**UI hint**: no

### Phase 3: Viewpoint grounding and specialist contracts

**Goal:** Viewpoint choices are framework-traceable, and the specialist set exists as orchestrator-dispatchable contracts covering vision responsibilities.
**Mode:** mvp
**Depends on:** Phase 2
**Requirements:** VIEW-01, VIEW-02, SPEC-01, SPEC-02
**Success Criteria** (what must be TRUE):

  1. Each selected viewpoint in the plan traces to stakeholder, concern, purpose, and abstraction level
  2. Non-standard viewpoint proposals include justification and stay ArchiMate-compliant
  3. Specialist skills/stubs cover the vision-enumerated list and are not the primary user entrypoints

### Phase 4: Coherence, create path, and compliance

**Goal:** Model writes go through inspect-before-create reuse and compliance validation that explains violations with alternatives.
**Mode:** mvp
**Depends on:** Phase 3
**Requirements:** SPEC-03, SPEC-04, COMP-01, COMP-02
**Success Criteria** (what must be TRUE):

  1. Create path inspects existing model content via MCP before adding elements and reuses matching concepts
  2. Compliance checks cover types, allowed relationships, abstraction, cross-view consistency, and naming
  3. Illegal changes are not applied silently; user sees explanation plus compliant alternative

**Plans:** 1/1 plans complete

### Phase 5: Rationale, summary, and live evidence

**Goal:** Significant views carry structured rationale; runs end with a completion summary; orchestrator path has live evidence under `docs/evidence/`.
**Mode:** mvp
**Depends on:** Phase 4
**Requirements:** RATE-01, RATE-02, RATE-03, EVID-01, EVID-02
**Success Criteria** (what must be TRUE):

  1. Significant views store structured rationale fields via MCP
  2. Natural-language change requests can regenerate views without breaking shared elements
  3. Orchestrator E2E evidence exists under `docs/evidence/` with a convention for later specialists
